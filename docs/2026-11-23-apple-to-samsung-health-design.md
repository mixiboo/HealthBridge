# 애플워치 운동 → Samsung Health 옮기기 앱 설계

작성일: 2026-11-23

## 1. 목적
애플워치로 기록한 운동을 갤럭시의 **Samsung Health에서 볼 수 있게** 하기.
- 꼭 필요: 운동 기록(종류, 시작·종료 시간, 칼로리, 거리)
- 되면 좋음: 심박수(특히 운동 중 심박), 운동 경로(GPS)
- 목표: 옮길 수 있는 데이터는 최대한 많이 옮기기

방향은 **애플 → 삼성 한쪽만**이다. Mac이 없어서 아이폰 앱은 만들지 않는다.

## 2. 목표 / 하지 않을 것 / 실패로 보는 것
**목표**
- 아이폰 건강 앱의 "모든 건강 데이터 내보내기" zip 파일을 갤럭시 앱에서 열기
- 운동, 심박, 경로를 Health Connect에 쓰고 Samsung Health가 가져가게 하기
- 같은 파일을 다시 가져와도 중복이 생기지 않게 하기(새 운동만 추가)

**하지 않을 것 (이번 버전)**
- 삼성 → 애플 방향
- 자동 동기화, 서버, 아이폰 앱
- HRV(애플·구글 계산 방식이 달라서 의미가 없음)

**실패로 보는 것 (작동은 해도)**
- Samsung Health에 운동이나 걸음 수가 **두 번씩** 쌓여서 기존 기록이 엉망이 되는 것
- 건강 데이터가 휴대폰 밖으로 나가는 것 → 앱에 인터넷 권한을 넣지 않는다

## 3. 제약
- 사용 기기: Galaxy S25+ (Health Connect가 시스템에 내장된 안드로이드 버전)
- 입력 파일: 애플 건강 앱 내보내기 zip
  - 한국어 설정이면 `내보내기.zip` 안에 `apple_health_export/내보내기.xml`, 영어면 `export.xml`
  - 경로는 `apple_health_export/workout-routes/*.gpx`
  - 파일이 수백 MB~1GB 이상일 수 있음 → 통째로 메모리에 올리면 안 됨
- Samsung Health가 Health Connect의 어떤 항목을 자기 화면에 보여주는지는 **실제로 써봐야 앎** (가장 큰 불확실성)

## 4. 고려한 방법
| 방법 | 장점 | 단점 |
|---|---|---|
| **A. 애플 내보내기 파일 + 갤럭시 앱** ✅ 선택 | Mac 불필요, 과거 기록 전부, 경로까지 포함 | 수동 내보내기, 파일이 큼 |
| B. 유료 아이폰 앱(Health Auto Export 등) + 갤럭시 앱 | 거의 자동 | 유료, 그 앱 형식에 종속 |
| C. VMware macOS로 아이폰 앱 직접 제작 | 완전 자동 가능 | 가상 환경 빌드 불안정, 무료 계정은 7일마다 재설치 |

사용자가 A를 골랐다. Mac 문제를 완전히 피하고, "최대한 많이" 옮기는 목표에 가장 잘 맞기 때문이다. 나중에 자동화가 필요하면 B를 입력 방식으로 추가할 수 있다.

## 5. 앱 동작 (사용자가 보는 흐름)
```
[파일 선택]  →  [미리보기]                    →  [옮기기]        →  [완료]
내보내기.zip     운동 132개 (2024-03 ~ 지금)      진행률 표시       새로 추가 12개
                 심박 기록 있음 ✓                                   이미 있음 120개
                 경로 98개 ✓                                         실패 0개
                 기간 선택 / 항목 선택
```
- 다른 앱(퀵쉐어, 내 파일, 카톡)에서 zip을 "이 앱으로 열기"로도 열 수 있게
- 항목 선택(기본값):
  - ✅ 운동 기록
  - ✅ 운동 중 심박수
  - ✅ 운동 경로(GPS)
  - ⬜ 하루 전체 심박수 (데이터 양이 많음)
  - ⬜ 안정 시 심박수, 체중 등 기타 항목
  - ⬜ 걸음 수, 수면 (갤럭시워치와 같이 차면 **중복**되므로 기본 꺼짐 + 경고 문구)

## 6. 내 판단으로 정한 것 (바꾸고 싶으면 말하기)
- **Kotlin + Jetpack Compose 네이티브 안드로이드 앱**: Flutter `health` 패키지는 운동 경로와 운동-심박 연결을 제대로 지원하지 않음. Health Connect 공식 SDK를 직접 쓰는 게 "최대한 많이"에 맞음.
- **스트리밍 XML 파싱**: zip을 풀지 않고 안에서 바로 한 줄씩 읽기(XmlPullParser). 큰 파일도 메모리 문제없이 처리.
- **중복 방지**: 각 기록에 고정된 ID(`clientRecordId` = 종류 + 시작 시간 + 종료 시간 + 원래 기기 해시)를 붙임. Health Connect는 같은 ID를 덮어쓰므로 다시 가져와도 중복이 생기지 않음.
- **애플워치 기록만 골라내기**: 내보내기 파일에는 아이폰, 다른 앱 기록도 섞여 있음. 기본은 애플워치 기록만, 원하면 전체로 바꿀 수 있게.
- **운동 종류 매핑**: `HKWorkoutActivityType*` → Health Connect `ExerciseSessionRecord.EXERCISE_TYPE_*` 표. 매칭이 없으면 "기타 운동".
- **운동 중 심박**: 운동 시작~종료 사이 심박 샘플을 `HeartRateRecord`로 같은 시간대에 기록 (Samsung Health가 운동 상세 화면에 그래프로 보여주길 기대, 테스트로 확인).
- **큰 작업은 백그라운드로**: 화면을 꺼도 계속되게 포그라운드 작업 + 진행률 알림. Health Connect에는 묶음(배치)으로 나눠서 씀.

## 7. 만드는 순서
1. **먼저 작은 실험** 🧪: 가짜 운동 1개 + 심박 + 경로를 Health Connect에 쓰는 버튼만 있는 앱 → Samsung Health에 어떻게 보이는지 확인. 결과에 따라 2단계 이후 범위를 조정.
2. zip 읽기 + 운동 목록 미리보기
3. 운동 + 운동 중 심박 옮기기 + 중복 방지
4. GPS 경로
5. 선택 항목(하루 심박, 기타 항목, 걸음·수면)

## 8. 만드는 사람에게 맡기는 것
- 화면 디자인 세부
- 운동 종류 매핑 표의 세부 항목
- 배치 크기, 오류 재시도 방식
- APK 빌드 방법(사용자 PC의 Android Studio 또는 작업 환경에서 빌드 후 전달)

## 9. 실험 결과 (Task 0, 2026-11-23, Galaxy S25+)
- ✅ 운동 목록에 "달리기"로 표시, 거리 5.00 km, 운동 시간 30:00
- ✅ 운동 중 심박: 평균 139 / 최대 160 bpm, 상세 화면에 심박 차트 표시 → 같은 시간대 HeartRateRecord 방식이 동작함
- ❌ 경로 지도: Samsung Health가 Health Connect 경로를 지도로 표시하지 않음 (데이터는 Health Connect에 저장됨)
- ❌→✅ 칼로리: ActiveCaloriesBurned만으로는 안 보임. v0.3에서 TotalCaloriesBurned도 쓰자 "운동 칼로리 250 kcal / 총 칼로리 250 kcal" 표시 확인
